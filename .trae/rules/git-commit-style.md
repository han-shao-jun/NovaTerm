# Git 提交日志风格规范

本规则用于规范 NovaTerm 项目的 Git 提交日志撰写风格，保证提交信息结构清晰、语义统一、便于检索与回顾。

## 一、整体结构

提交日志采用「标题 + 空行 + 正文」的三段式结构：

```
<type>: <中文简述>

本次提交完成<概述句>：

1.  <要点一>
2.  <要点二>
3.  <要点三>

同时<次要改动说明>。
```

- 标题与正文之间必须保留一个空行。
- 正文各段落之间以空行分隔，保持视觉层次。
- 每行宽度建议不超过 100 列，与项目注释规范保持一致。

## 二、标题行规范

采用 Conventional Commits 风格：

```
<type>: <中文描述>
```

- `type` 使用英文小写，常用类型包括：
  - `feat`：新增功能
  - `fix`：修复缺陷
  - `refactor`：重构代码（不改变外部行为）
  - `perf`：性能优化
  - `docs`：文档更新
  - `style`：代码风格调整
  - `test`：测试相关改动
  - `chore`：构建、脚本、依赖等杂项
  - `build`：构建系统或外部依赖变更
  - `ci`：CI 配置变更
- `type` 后紧跟英文冒号 `:` 与一个空格。
- 描述部分使用中文，简洁概括本次提交的核心内容，避免冗长。
- 标题行不加句号结尾。

示例：

```
feat: 新增系统资源监控面板与停靠面板折叠功能
fix: 修复 SSH 传输未连接时执行命令的崩溃问题
refactor: 重构终端渲染调度逻辑
```

## 三、正文规范

### 1. 概述句

正文以一句概述性话语引导，说明本次提交的整体目标或范围：

```
本次提交完成多项核心功能升级：
```

- 使用「本次提交完成……」或「本次提交主要……」句式。
- 以中文冒号 `：` 结尾，引出下文要点。

### 2. 编号要点列表

使用阿拉伯数字编号列出本次提交的具体改动：

```
1.  添加远端系统资源监控面板，支持实时查看 CPU、内存、交换分区和网络流量
2.  为可停靠工具面板新增折叠/展开功能，支持按停靠方向自动适配图标
3.  扩展 SSH 传输类，支持异步执行辅助命令并做流量与超时限制
4.  新增退出确认配置项，可自定义关闭程序时是否弹出确认对话框
5.  完善窗口布局保存逻辑，新增工具面板折叠状态与尺寸的持久化
6.  补充多语言翻译文件，适配新增功能的文本展示
```

规范要点：

- 编号与文本之间使用两个空格分隔（`1.  `），保持对齐。
- 每条要点以动词开头，例如：添加、新增、扩展、完善、补充、修复、优化、重构。
- 一条要点聚焦一项改动，避免合并多个不相关的内容。
- 描述需具体到可被检索的程度，避免「修改若干问题」「更新部分代码」等空泛表述。
- 中文与英文/数字之间保留一个空格，例如 `CPU、内存`、`SSH 传输类`。
- 列表项不使用句号结尾。

### 3. 收尾补充句

正文末尾使用一段补充说明，总结次要改动或附加影响：

```
同时修复了 SSH 传输未连接时的命令执行风险，优化了停靠面板的交互体验。
```

- 使用「同时……，……。」句式串联次要改动。
- 句末使用中文句号收尾。
- 仅包含与本次提交相关、但未列入编号要点的次要改动；若无此类改动可省略。

## 四、语言与术语

- 提交日志以中文为主，保留以下内容为原文：
  - 代码标识符（类名、函数名、变量名）
  - 协议与标准名称（SSH、SFTP、VT100、ConPTY 等）
  - 通用技术缩写（CPU、GPU、RAM、IO 等）
- 中文与英文/数字之间保留一个空格，提升可读性。
- 避免使用口语化表达与表情符号。

## 五、参考样例

完整样例：

```
feat: 新增系统资源监控面板与停靠面板折叠功能

本次提交完成多项核心功能升级：

1.  添加远端系统资源监控面板，支持实时查看 CPU、内存、交换分区和网络流量
2.  为可停靠工具面板新增折叠/展开功能，支持按停靠方向自动适配图标
3.  扩展 SSH 传输类，支持异步执行辅助命令并做流量与超时限制
4.  新增退出确认配置项，可自定义关闭程序时是否弹出确认对话框
5.  完善窗口布局保存逻辑，新增工具面板折叠状态与尺寸的持久化
6.  补充多语言翻译文件，适配新增功能的文本展示

同时修复了 SSH 传输未连接时的命令执行风险，优化了停靠面板的交互体验。
```

修复类样例：

```
fix: 修复 SSH 通道断开后残留定时器导致的崩溃

本次提交主要解决以下问题：

1.  清理 SshTransport 析构时未释放的辅助命令定时器
2.  修正流量统计在连接异常关闭后的累计错误
3.  补充断连场景下的单元测试覆盖

同时优化了日志输出，便于后续排查同类问题。
```
