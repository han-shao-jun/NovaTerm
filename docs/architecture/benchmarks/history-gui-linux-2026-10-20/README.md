> 文中输出文件名用于标识重跑产物，已不在仓库中；重跑生成的是新样本。

**默认压缩的热区响应接近 OFF，但冷历史翻页/跳转 P95 未达到 50 ms 目标。**

## 响应延迟：OFF 与默认压缩

单位 ms，P95 / P99 均为三个进程各自分位数的中位数。采样时的 JSON 包含每轮及 min/max（已清理）；
不是合并三轮分位数。完成标记要求该视口映射先经过全量重建，且历史与字形均已就绪。

| 语料 | 场景 | OFF P95 / P99 | 默认压缩 P95 / P99 | 默认组各轮 P99 最大值 |
| --- | --- | ---: | ---: | ---: |
| variable | 热区滚轮 | 34.18 / 34.54 | 34.43 / 34.86 | 34.95 |
| variable | 冷区逐页 | 34.77 / 35.88 | 51.33 / 66.72 | 66.74 |
| variable | 冷区滚动条跳转 | 34.45 / 34.77 | 68.24 / 83.41 | 84.01 |
| variable | 持续输入下连续滚轮 | 33.73 / 34.61 | 34.20 / 35.78 | 37.59 |
| mixed | 热区滚轮 | 34.39 / 34.96 | 34.73 / 34.94 | 35.25 |
| mixed | 冷区逐页 | 34.88 / 35.37 | 51.28 / 66.73 | 66.74 |
| mixed | 冷区滚动条跳转 | 34.66 / 34.87 | 67.63 / 68.21 | 68.39 |
| mixed | 持续输入下连续滚轮 | 33.82 / 34.61 | 34.04 / 34.75 | 40.19 |

前三项逐请求等到正确目标帧后，再按不快于 60 Hz 的节拍发下一次，是闭环延迟实验。
它们的帧间隔受输入节拍/等待影响，不能用其约 30/18 Hz 的更新率宣称连续滚动帧率上限。
冷区测试允许自然缓存命中；cache hit/miss 与 Pending 另列，并非声称每次翻页必定解压。
热区组 cache miss 为 0，冷区组确实进入异步历史读取。

第四项由独立线程每 16.667 ms 投递滚轮，并在每次投递前注入 16 行日志，目标约 960 行/秒。
最新请求延迟会隐藏被合并请求的等待，因此必须同时看下面的最早请求批次等待和内容更新间隔。

## 连续滚动流畅度与合并

以下为每进程指标的三轮中位数。正确内容间隔只在新的目标历史实际提交时计数；
重复绘制旧画面的 GPU 帧另列在 JSON。超 33.3 ms 比例分母为相邻正确内容更新间隔数，
是应用更新节奏指标，**不是合成器/显示器掉帧率**。16.7 ms 门槛也保留，可能包含刷新/计时抖动。

| 语料 | 策略 | 最新请求 P99 ms | 最早合并请求→帧 P99 ms | 正确内容间隔 P99 ms | 正确内容 fps | 合并比例 | 内容间隔 >33.3 ms |

| variable | off | 34.61 | 51.83 | 51.81 | 40.2 | 32.8% | 30.6% |
| variable | on-default | 35.78 | 81.84 | 67.66 | 44.9 | 24.2% | 18.8% |
| variable | on-small | 32.86 | 48.55 | 35.03 | 52.1 | 12.5% | 8.1% |
| variable | on-hot | 35.71 | 81.70 | 66.73 | 40.9 | 32.0% | 31.0% |
| mixed | off | 34.61 | 50.61 | 51.33 | 36.6 | 38.3% | 41.0% |
| mixed | on-default | 34.75 | 66.10 | 51.44 | 42.1 | 29.7% | 29.2% |
| mixed | on-small | 34.36 | 99.09 | 99.95 | 34.7 | 41.4% | 37.8% |
| mixed | on-hot | 35.07 | 82.53 | 66.77 | 40.4 | 32.0% | 30.2% |

例如 mixed 的 on-small 虽然最新请求 P99 约 34 ms，但最早合并请求等待约 99 ms、
正确内容更新间隔 P99 约 100 ms。仅看最新请求或总 GPU 帧数会掩盖这类停顿。
所有 12288 个事件均已处理，合并是 latest-target-wins，不是输入或历史字节丢失。

## 块大小、热区、CPU 与内存取舍

`on-default` 为 512 KiB 块 / 4 MiB 热区；`on-small` 仅改成 256 KiB 块；
`on-hot` 仅扩大至 8 MiB 热区。缓存/队列/工作区限额不变，均是基准实例的策略，
不写应用配置。初始 charge 在预填与后台压缩排空后、滚动前采集，包含共享工作区，非 RSS。

| 语料 | 策略 | 初始 charge MiB | 相对 OFF 节省 | 预填整进程 CPU ms | 冷跳转 CPU ms / 128 次 | 冷跳转 P95 / P99 ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| variable | off | 189.28 | 0.0% | 1534.6 | 1627.2 | 34.45 / 34.77 |
| variable | on-default | 14.98 | 92.1% | 1805.8 | 2095.0 | 68.24 / 83.41 |
| variable | on-small | 15.31 | 91.9% | 1804.6 | 2119.2 | 68.33 / 84.09 |
| variable | on-hot | 19.06 | 89.9% | 1754.9 | 1945.4 | 67.66 / 68.59 |
| mixed | off | 194.61 | 0.0% | 1438.3 | 1665.6 | 34.66 / 34.87 |
| mixed | on-default | 14.96 | 92.3% | 1742.6 | 2112.4 | 67.63 / 68.21 |
| mixed | on-small | 15.52 | 92.0% | 1807.0 | 2104.5 | 67.78 / 69.23 |
| mixed | on-hot | 19.07 | 90.2% | 1744.7 | 2159.9 | 67.99 / 83.14 |

本轮默认策略在这种合成日志上的 charge 下降约 92%；它与之前六类无 Qt 语料的约 74%
属于不同内容/负载，不能作代码前后优化比较。进程 CPU 包含 Parser、生成、GUI、worker、
事件循环和基准记账，不等于纯 codec CPU，也不是固定接收 MiB 的生产 CPU 验收。
RSS/peak RSS 保留每个进程原值；Linux statm/ru_maxrss 的口径尚未校准，不能当严格内存上界。

热区 Renderer CPU P95 的默认/OFF 中位数比值：

- variable：6.061 / 6.254 ms（OFF / ON），ON/OFF=1.032。
- mixed：6.015 / 6.338 ms（OFF / ON），ON/OFF=1.054。

本轮取舍结论：

1. 256 KiB 小块增加了冷请求未命中计数，未稳定降低冷跳转延迟；mixed 连续滚动尾延迟反而较差，
   不据此替换默认块大小。cache_misses 包含重试查询，不等同于实际解压任务数。
2. 8 MiB 热区比默认多约 4.1 MiB charge；variable 冷跳转 P99 有改善，但 mixed 从约 68 ms
   变为约 83 ms，且两种语料 P95 仍约 68 ms。收益没有跨语料一致性，不据此扩大默认热区。
3. 继续保留 512 KiB / 4 MiB 作为后续优化对照、开关默认 false。下一步优先验证视口跨块的
   冷读请求合并/预取及完成唤醒到完整绘制的调度往返，随后用同矩阵确认响应、CPU、内存同时改善。
   当前延迟接近若干刷新周期，源码的 CacheOnly 等待→historyDataReady→完整重绘路径与此一致，
   但尚无函数采样/逐阶段耗时，以上是待验证瓶颈假设，不声称已定位各部分占比。
