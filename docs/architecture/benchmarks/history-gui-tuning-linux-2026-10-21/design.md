# 三轮参数调整与提交计划

> 归档清理：可重跑生成的 JSON、日志及重复表格已移除；本文保留历史结论。
> 文中输出文件名用于标识重跑产物，已不在仓库中；重跑生成的是新样本。

用户明确要求再做三轮调整，比较后选择参数，完成后提交并推送 master。
保留此前全部未提交代码、基准和样本；不覆盖 2026-10-20/21 历史报告。

原参数 512 KiB 块/4 MiB 热区作为固定 reference，不随最终生产默认值漂移。
三轮调整分别为 384 KiB/4 MiB（只改块）、512 KiB/2 MiB（只改热区）、
384 KiB/2 MiB（组合）。所有共享缓存、队列、单块上限及临时工作区预算不变。

统一比较矩阵为两语料 × 五策略（OFF、reference、三个调整）× 三独立进程，
共 30 个进程，各进程仍为 50000 行、四场景各 128 次请求、60 Hz。策略按轮次换序。
先使用本机 P 核集合 0–15 进行同类核心成本比较，明确记录继承的亲和性；
随后使用默认调度复核 OFF/reference/胜出参数，每项两语料各三独立进程。
构建、采样与其他测试分开，保留所有原始请求与最终像素检查。

预先固定选择规则：

1. 两语料每进程分位数的三轮中位数均满足冷区 P95≤50 ms、P99≤100 ms；
   热区 Renderer P95 相对本轮 OFF 中位数不超过 1.10；同内容 charge 节省至少 40%。
   同时报告单轮最大值，不用中位数隐藏越界。
2. 合格组比较两语料最差的冷区 P99、最早合并请求等待 P99、正确内容间隔 P99。
   这些指标最差值取最大为尾延迟分数；分数距最优不超过 5 ms 时视为接近，优先较低 charge，
   再比较进程 CPU 与尾延迟。该接近阈值不替代统计显著性检验。
3. 没有调整组稳健优于 reference 时保留 reference；不得为“必须改参数”牺牲 CPU 或内存。
4. 默认调度结果单独报告；同类核心对照不能覆盖默认环境的门槛失败。

选定后只修改策略默认值，压缩 enabled 继续 false，历史完成标记及 GPU self-test 判据不改。
运行相关 History/Core/Scrollback/Renderer 及 GPU 检查；按 AGENTS 提交约定递增版本，
使用中文消息说明结果和缺口，创建单一主题提交并推送 origin/master，不创建 PR、不强推。
