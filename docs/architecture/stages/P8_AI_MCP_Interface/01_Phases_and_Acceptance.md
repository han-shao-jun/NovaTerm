# BSP 终端闭环的实施顺序与验收

更新：2026-10-25。当前状态：B0 本轮基线/日志子契约与 B1 已实施，见 [B0/B1 实施与验收](records/B0_B1_Implementation_2026-10-25.md)。B2/B3/B4 未实施，B0 其余子契约随对应批次冻结。B0～B4 是本次闭环任务编号，B3a/B3b 为交互扩展子批次；旧 mcp/P0～P8 不再作为实施路线，项目顶层 P0～P9 编号不变。

## 1. 收口目标

外部 Agent 能选中获准的 SSH/UART，观察当前屏幕，建立日志书签，操作设备并有界等待，持续读取新增缓存；重启、超时、缺口和人工接管时不误判、不盲重放。通过真实 BSP 项目完成至少一次编码→构建→上板→观察→修复→复验，由外部 Agent 编排。

不以“工具数增加”“通用平台完备”或“有聊天 UI”作为完成条件。源码缺口映射见 [03](03_Gaps_and_Evidence.md)。

## 2. B0：固定现状与冻结契约

对应 G02、G04、G07～G11、G13～G17；为后续实现的前置。字段与预算分批冻结，B1 不等待文件/连接扩展的全部实现细节。

- [x] 记录工作树、构建配置、实际 tools/list 与冻结十二工具 fixture 的差异，单列并退役未发布 P4 两项扩展；按消费者完成内部清理，不能把已有未提交代码当全绿基线。
- [x] 冻结 read_context 显式日志选择、tail/oldest 初始定位、游标类型、分页/缺口字段及错误码。缺省旧观察行为兼容，不以 full/compact 暗改数据源。
- [ ] 冻结清空工具名称、权限、范围、操作 ID/幂等、完成通知与新基线；说明本机菜单清空如何触发相同失效。
- [x] 统一两代 MCP instructions、工具描述和使用文档，准确说明完整输入授权、UART 静默证据和未知结果。
- [ ] 冻结条件等待的来源/起点/匹配/续扫，异步任务的受理/查询/停止/断流语义，以及文件/目标连接的独立权限和幂等；具体有限预算随对应子批次冻结，不能带无限默认值上线。
- [x] 确认已有测试目标/fixture 和实际可用构建路径；未创建的测试不写成已经注册。

退出：现行契约与新增设计可以逐字段区分；每个改变均有消费者、owner、失效条件与测试落点。不要先搭建新的 Agent/诊断框架。

## 3. B1：准确读取缓存与屏幕（本轮实现）

对应 G01～G03、G06。

- [x] 经现有 Core/Scrollback 窄接口获得稳定缓存位置和有界历史片段，复用现有快照/历史块能力，不建立第二日志库。
- [x] 建书签不清空；日志保留真实重复行，历史/活动屏幕交界按身份处理。
- [x] 分页只推进已交付位置，超长 UTF-8 行可以续读；慢客户端读到已淘汰位置明确报告缺口。
- [x] 区分暂时块未就绪、源已缺失、本次预算不足和已追上本次上界；多个客户端/会话的游标互不推进。
- [x] 保留未换行、CR 覆盖、alternate screen 的屏幕观察；旧 full/compact/expand 和输入 token 回归。

退出：可控替身日志中重复行数/顺序正确；小预算串接结果等于同一保留范围的大预算结果；淘汰时不伪造完整，持续输出不阻塞 UI/Parser。

## 4. B2：清空与代际

对应 G04、G05。

- [ ] Core 清空完成产生可关联事实，复用 Parser 命令队列及字节屏障，失败入队不返回成功。
- [ ] 应用用例统一授权、操作去重、等待/取消；Session 统一发布代际，协议层不直接改 Core/UI 缓存。
- [ ] 清空完成后旧日志游标与实时投影按契约失效，返回新基线；期间新输出不被重复清空吞掉。
- [ ] 本机菜单和 MCP 清空走一致边界；独立录制/历史共享不随实时清空删除。
- [ ] 覆盖队列满、清空与输入并发、撤权、断连、客户端丢响应后的精确重试，以及清空前后 UTF-8 文本。

退出：只读用户不能清空；成功表示 Parser 已生效；相同操作重试不清除后续输出；旧游标失败明确。

## 5. B3：SSH/UART 交互与恢复

对应 G07～G11、G14～G17。设计详见 [06](06_Terminal_Workflow_Extensions.md)。

- [ ] 复用已有 Controller/Arbiter/CommandRuntime，验证 Linux Shell、U-Boot 风格提示、登录提示、无提示符设备和 TUI。
- [ ] text/key/line_ending 与 command 就绪规则清楚，CR/LF/CRLF、Ctrl+C、Tab、方向键按目标测试。
- [ ] 验证静默长任务和迟发错误不被 Agent 使用说明判为成功；保持既有结果字段兼容，新增证据语义显式演进。
- [ ] 超过单次 30 秒的任务用后续等待观察；取消读取、取消命令和释放控制分别验证。
- [ ] 人工接管、撤权、旧 inputToken/replyToExecutionId、operationId 冲突、SSH 重连、UART 同链路重启均不产生错目标或重复输入。

退出：替身/集成测试能证明已提交、完成、未知与测试结果分离；实际客户端理解工具说明并完成多轮观察，而非凭一次响应决定结果。

### B3a：文本等待和长任务

依赖 B0/B1；清空相关失效与 B2 一起验证。对应 G14/G15，并补齐 G10/G11。

- [ ] 提供字面文本条件等待，显式日志/屏幕来源及新旧文本起点；跨页/UTF-8 匹配与预算续扫不漏读、不无限扫描。
- [ ] 匹配成功只返回证据，不能把 PASS 文本或 UART 静默直接映射成任务成功；超时、缺口、撤权和取消分别返回。
- [ ] 提供长任务启动/查询/停止，复用现有执行 owner，taskId 绑定客户端/Session，精确重试不重复输入；状态与日志保留分离。
- [ ] SSH 保留当前终端状态，UART 不要求 Shell 包装；完成证据和可停止性按实际能力声明。
- [ ] 人工接管后旧 stop 零输入；断流后可查询受理结果，重启失去记录不重放；任务/结果/等待者都有有界回收。
- [ ] 两代握手和工具说明一致，指导本地构建、板上操作、日志/屏幕读取和短/长任务选用；未实现扩展不推荐调用。

退出：老 PASS 不触发新轮次；大日志等待不阻塞界面；长任务查询不再次执行；UART 无可靠证据时不报告成功。

### B3b：文件传输和保存目标连接

依赖 B0 及现有 SSH/SFTP/Profile/Session 创建边界；不阻塞 B1/B3a 首批交付。对应 G16/G17。

- [ ] 增加受限单文件上传/下载及进度/取消；使用本地授权资源引用和远端路径权限，默认不覆盖，不开放任意本机文件读取。
- [ ] 路径替换/链接逃逸/发布竞争复核；返回字节传输、发布和校验各自事实；未知发布不能自动重试覆盖，临时文件仅清理自身所有物。
- [ ] 增加获准保存目标目录、打开/复用、连接状态及关闭入口；不修改保存配置或认证，不新建后台 Session owner。
- [ ] 新连接共享规则由用户预先选择，打开权限不自动授予输入；相同操作重试不多开标签，旧配置版本拒绝。
- [ ] 复用的人类会话不能作为任务清理关闭；人工接管、忙碌传输/执行、认证待处理和串口占用明确返回。

退出：单文件交付不执行部署命令；目标连接不越过保存目标/权限边界；文件与连接副作用均有可查询结果和幂等证明。

## 6. B4：真实 BSP 闭环与性能

对应 G09、G12 及已交付的 G14～G17。需要用户明确目标设备与允许的部署/重启操作后执行，不自动连接历史服务器或占用串口。先验证基础日志/交互批次，再分别补验扩展，未测扩展不能计入完成。

| 验收 | 具体判据 |
| --- | --- |
| SSH Linux | 明确目标/固件版本，执行测试，读取结果；断连后旧身份不重放 |
| UART 启动 | 重启前连通，慢读分页后能读到仍保留的早期日志；缺口明确 |
| UART 交互 | 用户指定设备的提示符/行结束符/控制键；未知状态不乱发 Shell 包装 |
| 双通道 | 明确同板配对，SSH 中操作、UART 观察；两者各自游标/epoch，不共享控制进度 |
| 失败再修复 | 外部 Agent 编码/构建/部署/观察发现一个可控失败，再修复复验；每步结果可归属本轮 |
| 清空 | 本机与 MCP 清空后旧游标失效，精确重试不删除新输出 |
| 条件等待 | 上轮同名标志不误触发；当前屏幕未换行提示可匹配；清空/淘汰/超时均不伪装成功 |
| 长任务 | 超过单次等待上限仍可查询；SSH/UART 证据差异明确；重复启动和人工接管后的停止不误写 |
| 文件交付 | 上传一份实际构建产物、下载测试日志；验证字节/发布/校验及断连恢复事实，不自动烧录 |
| 保存目标连接 | 受限目标打开/复用/查询/关闭；不重复开标签、不关闭人类会话，认证和串口占用能退出等待 |
| 持续输出 | 负载、波特率、驱动 RX 队列、缓存配置和消费者速度可复现；区分驱动丢帧/缓存淘汰/投影裁剪 |
| 交互时延 | 单列观察延迟、快照年龄和输入提交延迟；U-Boot 短倒计时没有实测就不承诺 |

性能沿用可对比的目标口径：同会话新采样需求合计不超过 4 Hz、最多 4 客户端时，有效读取响应率目标 ≥99%，成功 RPC P95 ≤100 ms（不计主动等待），GUI 捕获 P95 ≤2 ms；相同输入负载 MCP 开关对照吞吐下降 ≤5%，GUI frame P95 增量 ≤2 ms。它们是待测门槛，不是本轮成绩；新日志页需要另记录字节量/冷块状态，不混用负载。

过载允许明确 Busy/缺口，但队列、内存、缓存固定量有上限；记录各客户端最长无成功间隔，不用快速 Busy 充当低延迟成绩。现有串口压力夹具和历史性能报告提供起点，不替代本轮设备验收。

## 8. 完成定义

每项须同时具备实现、对应回归、协议/使用文档及该范围验收记录；分别报告替身、真实 SSH/UART、客户端、平台和性能。历史全套成绩不能覆盖当前未提交改动。B1/B2 未完成前不得对外宣称“可靠日志分页和清空闭环已支持”；B4 未完成前不得宣称真实 BSP 闭环验收通过。

B3a/B3b 各自通过实现、专项与对应真机验收后才能标记扩展完成。文档补齐不注册新工具、不修改测试成绩，不以基础终端批次通过代替文件/连接能力验收。
