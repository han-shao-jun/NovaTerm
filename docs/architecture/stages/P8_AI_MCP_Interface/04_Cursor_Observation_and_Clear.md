# 终端缓存游标与清空设计

2026-10-25。B1/B2 已实施，精确字段及状态以 [现行契约 B1/B2](02_Current_MCP_Contract.md) 为准；本页第 5 节清空事务已实施，具体权限/票据/期限与错误以 02 的 B2 契约为准。实施范围及测试见 [B0/B1 实施与验收](records/B0_B1_Implementation_2026-10-25.md) 与 [B2 实施与验收](records/B2_Implementation_2026-10-25.md)。

## 1. 数据源与两种读取

日志直接来自 TerminalCore/Scrollback 的解析后终端文本，屏幕来自现有不可变快照。不另建 raw UART 采集、持久日志数据库或第二条输入流；解析后文本不承诺保留原始 ANSI 字节、覆盖前的屏幕帧或所有终端控制序列。

| 读取 | 用途 | 定位 |
| --- | --- | --- |
| 屏幕观察 | 登录提示、U-Boot、REPL、top、进度条、当前光标位置 | 当前 model revision、viewport、状态和捕获时间 |
| 日志增量 | 启动日志、测试输出、重复报错及其顺序 | 缓存代际、稳定历史位置、必要的 UTF-8 字节偏移 |

不能按文本内容去重真实日志。屏幕行进入历史时使用稳定来源身份处理交界，不重复拼接 viewport 与历史，也不因为内容一样而合并两条真实记录。活动屏幕与仍在续接的历史软尾行以屏幕观察提供，不为它建立版本日志；重连后成为非尾部的旧软行按稳定片段读取，以 hardBreak=false 明示并保留无 LF 的实际边界。

## 2. 对外演进方向

B1 已在 read_context 增加**显式选择日志读取语义**的兼容扩展，复用 sinceToken/nextToken 命名；缺省仍为旧观察模式。full/compact 继续表示投影预算，不偷偷改为“全文日志/摘要”两种数据源。

旧观察游标与新日志游标必须有类型/版本标记，跨模式使用明确拒绝。现有 expandToken 只补读固定观察 capture，不用于日志位置推进。B0/B1 已冻结并实施 source=log、start=tail|oldest、分段与三类位置 token，见 02；日志首版不接受非零 waitMs，条件等待在 B3 扩展。

清空使用独立、显式的变更操作；不塞入 text/key 或伪装成只读工具。具体名称、Schema 和十分钟幂等窗口已在 02 的 B2 契约中冻结。能力未实现时不注册空壳工具。

## 3. 书签和分页语义

服务端签名游标包含版本、可信客户端/授权绑定、Session/epoch、缓存代际和下一个读取位置；模型不能修改声明绕过权限。读取本身不取得输入权。

- 无游标时显式选择“当前尾部建立书签”或“当前保留的最早位置开始读”。B1 初次必须显式传 start=tail|oldest，续读传 sinceToken；准确字段见 02，工具说明必须解释；不能为建书签先清空历史。
- “从现在开始”以成功返回的快照/历史发布边界为准，不声称覆盖调用前尚未接收的数据。
- 每次读取确定一个上界，只返回有界文本。nextToken 指向**最后实际交付位置之后**，不能直接跳到尚未返回的最新 model revision。
- 页受字节/行数限制时返回还有可读内容的事实及续读 token。只有已读到本页采样上界才报告追上；它不意味着设备停止输出。
- 超长行按 UTF-8 标量边界分段；至少容不下一个标量时明确报预算错误，不返回原 token 的无限空页。
- 相同游标重试是无副作用读取；缓存仍保留时位置解释一致。新输出可以延长可读范围，不承诺整个响应字节永久相同。
- 返回日志行身份/分段位置，使客户端可消除传输重试导致的重复展示；不同位置的相同文本必须保留。
- 日志首版 waitMs=0；后续等待只等待变化/可读数据，不阻塞 GUI，不在工具内无限轮询；单次等待到期后仍可用有效书签继续。

## 4. 不完整与失效

| 情况 | 必须表达的结果 | Agent 的下一步 |
| --- | --- | --- |
| 单次响应预算不足 | 还有内容、精确续读位置 | 继续分页，无需重建基线 |
| 请求位置已被缓存淘汰 | 缺口、当前可读起点；丢失数量无法确定时不编造 | 承认日志不完整，再从获准起点读取 |
| 本机或控制序列清空（含 B2 MCP 清空） | 缓存代际变化、旧游标失效 | 获取新基线，不把旧位置套用到新缓存 |
| Session 重连/替换、撤权 | 绑定失效或拒绝访问 | 重新列会话/授权核对，不重放旧写操作 |
| 同链路板子重启 | 保留串口连接事实，输出可能跨启动轮次 | 根据启动标志/固件标识判断；不凭猜测清空或换代 |
| 后台历史块未就绪 | 明确稍后重试/不可用，不伪装成空日志 | 有界等待或稍后重读 |
| 原始串口数据在驱动前后丢失 | 仅报告已有可信统计能证明的事实 | 不用“日志分页完整”宣称原始 UART 字节零丢失 |

新日志读取应区分“预算分页”和“源已缺失”，不继续把二者都塞入一个 resetRequired。旧观察契约已有字段保持兼容。授权撤回之后任何旧 token 都不能恢复读取。

## 5. 清空事务

清空范围为“滚动历史”或“屏幕及滚动历史”，由 Agent 显式选择。它会影响人的本地终端视图，必须有明确的变更授权；仅有读取权限不能清空。B2 在终端共享中独立授予 ClearTerminal，默认关闭；不复用或隐式升级旧输入 grant。

1. 校验可信客户端、会话绑定、授权版本、操作 ID 和当前代际。
2. 经 Session 窄接口提交到现有 Parser 命令队列，复用字节屏障；不直接改 UI 或 Provider 私有缓存。
3. 队列拒绝则明确失败，不能返回清空成功；队列接受仅表示已受理。
4. Parser 执行后推进清空代际并发布完成事实。Session 使相关日志游标和旧实时投影失效，再返回新基线；禁止用阻塞 GUI 的 waitForIdle 等待。
5. 相同操作 ID/参数重试返回原结果，不再次清除新日志；参数冲突拒绝。完成未知时不换 ID 自动重发。

输入与清空重叠时，以 Controller 的 GUI 回调内最后一次成功代际复核为输入受理点；在该点前已清空的旧输入拒绝，该点后已开始的提交可与 Parser 清空重叠，清空 GUI 完成通知须等当前同步回调结束。具体边界见 02，不通过持有模型锁进行 Transport I/O。

不向设备发送 clear/reset/Enter，不停止远端程序，不重连，不修改终端模式，不清除独立录制和离线共享资源。清空之后立即到达的新输出允许出现在屏幕上，不承诺响应时终端仍为空。

旧 capture 的处置要一致：实时观察 capture 在清空边界后不可继续伪装成当前文本；已经返回给 Agent 的内容无法追回，独立历史资源依其原授权规则处理。MCP 清空和本机菜单清空必须共用同一个失效源。

## 6. 模块边界与验证

- Core/Scrollback 拥有文本、稳定位置、淘汰和清空完成事实；MCP 不复制一份全量日志。
- Session 拥有连接、代际和生命周期适配；读取端口仅返回有界值/不可变片段，不暴露 Transport/Core 可变指针。
- 应用用例负责读取授权、预算、等待和清空幂等；协议适配负责 token 编解码、Schema 和错误映射。
- UI 只提交清空意图并显示结果；不成为日志游标真源。
- 为历史访问选择现有有界 chunk/snapshot 接口，避免在 GUI 上遍历全量历史或等待冷块；不无界固定旧块阻止正常淘汰。

验收覆盖重复行、跨页超长 UTF-8 行、缓存淘汰、慢消费者、清空竞争、队列满、旧 token、撤权、重连、未换行/CR 覆盖、alternate screen、多个客户端/SSH-UART 独立进度及 Parser 不受 MCP 背压。分阶段执行见 [01](01_Phases_and_Acceptance.md)。
