# MCP 统一接入与授权

用户明确选择：所有 AI 共用一套接入与授权，彻底取消按客户端区分。

## 交付范围

- MCP 界面只保留启用、复制配置、重置接入令牌及现行授权；删除客户端选择与增删管理。
- 所有持有统一令牌的连接使用同一个内部授权主体。终端、文件、串口发送、历史录制和导入资源均共享这套授权。
- 保留内部主体 ID、身份代际和连接绑定作为失效校验；它们不再表示用户需要管理的不同 AI 客户端。
- 状态格式升级为单接入记录；旧多客户端令牌不继续认证，旧授权不取并集。重新启用后生成统一配置；按用户后续要求，会话权限默认全开，文件和历史共享仍独立选择。
- 初次启用自动创建统一令牌；读取状态不主动解锁系统凭据库。重置令牌使旧令牌及原身份绑定失效，停用撤销运行期权限。
- 文件授权、历史共享与导入 UI 不再展示客户端选择；权限种类、连接代际、终端输入和独立文件权限边界保持。
- 用户后续明确移除保存目标表格，MCP 只暴露已经连接的会话。删除 list_targets/open_target/query_target/close_target 四工具及独占实现，当前26→22工具；保存连接的本机手动管理保持。此前列宽修复被删除整张表替代。
- 已连接及以后新就绪连接的读取、完整输入、提权选择和清空默认全开；同连接上手动取消后普通刷新不恢复。提权后端可用性仍独立检查。
- 使用用户指定的 scripts/build-novaterm_com.bat 构建。不自动提交、推送或连接设备。

## 方案选择

仅隐藏客户端管理仍保留多套实际权限，不符合用户选择；因此采用单接入记录并统一协议入口的授权主体。底层领域服务的通用身份参数保留，用于验证旧请求和资源代际，不为删名重写已验证的传输状态机。

## 验证重点

新配置自动建立、两连接共享权限、旧格式拒绝及迁移、重置/停用/跨实例刷新失效、凭据与保存失败不发布半完成配置；22 工具及四个保存目标旧工具拒绝、断开会话不列出、默认权限不覆盖人工取消，经相关测试与独立行为复核后交付。
